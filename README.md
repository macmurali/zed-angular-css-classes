# Angular CSS Classes for Zed

Jump from a class name in an Angular template to the CSS/SCSS/Less rule that defines it.

| In a template (`.html`) | In a stylesheet |
|---|---|
| **Go to Definition** (F12 / ⌘-click) | **Find All References** → every template using the class |
| **Hover** shows the rule | |
| **Completion** inside class attributes | |
| **Find All References** | |

Understands all the usual Angular forms:

```html
<div class="card is-active {{ big ? 'card--big' : '' }}"
     [class.card--selected]="selected"
     [ngClass]="{ 'card__body': open, card__footer: !open }"
     [class]="'btn btn--primary'"></div>
```

and SCSS/Less nesting such as `.card { &__title {} &--active {} }`, escaped selectors (`.md\:flex`), and `@use` / `@import` partials.

### Which definition wins

When a class is defined in several places, Go to Definition returns only the most relevant tier:

1. **The component's own styles** — `foo.component.scss` next to `foo.component.html`, or whatever `styleUrl`/`styleUrls` the component's `.ts` points at — plus everything they `@use`/`@import`.
2. **Global styles** — the `styles` arrays in `angular.json` / `project.json` (plus their imports) and any `extraStylePaths`.
3. **Anything else** in the workspace.

Set `showAllDefinitions: true` to get every match instead.

## Install (dev extension)

Requirements: Rust installed via **rustup** (Zed compiles the extension to WebAssembly itself).

1. Clone/unzip this folder somewhere permanent.
2. In Zed: command palette → **`zed: install dev extension`** → pick the folder.
3. Open an Angular project and an `.html` template. **`dev: open language server logs`** should show `angular-css-classes` with an `indexed N stylesheets` line.

For proper Angular template highlighting also install the **Angular** extension; this one works alongside it (and alongside the Angular Language Service). When several servers answer Go to Definition, Zed shows all results.

## Settings

Optional, in `settings.json`:

```jsonc
{
  "lsp": {
    "angular-css-classes": {
      "initialization_options": {
        // also index a library's stylesheet (relative to the workspace root)
        "extraStylePaths": ["node_modules/bootstrap/dist/css/bootstrap.css"],
        "showAllDefinitions": false,
        "styleExtensions": [".css", ".scss", ".less"],
        "exclude": ["node_modules", ".git", "dist", ".angular", "coverage"],
        "maxFiles": 20000
      }
      // "binary": { "path": "node", "arguments": ["/path/to/angular-css-lsp.js", "--stdio"] }
    }
  }
}
```

`node_modules` is excluded by default; use `extraStylePaths` for the library stylesheets you actually want (Bootstrap, Material, etc.).

For example, if Font Awesome is installed from npm and not listed in `angular.json`'s `styles`, add:

```jsonc
"extraStylePaths": ["node_modules/@fortawesome/fontawesome-free/css/all.css"]
```

## How it works

`src/lib.rs` is the Zed extension. It embeds `server/angular-css-lsp.js` — a small language server with **no npm dependencies** — writes it into the extension's work directory, and runs it with Zed's bundled Node. The server indexes stylesheets on startup and watches the workspace for changes.

```
extension.toml          manifest, attaches the server to HTML/Angular/CSS/SCSS/Less
Cargo.toml, src/lib.rs  the Zed extension (Rust → WASM)
server/                 the language server (plain Node.js)
test/                   fixture Angular project + end-to-end LSP test (`node test/lsp-test.js`)
```

## Limitations

- Inline `template:` strings in `.ts` files aren't scanned (only `.html` templates).
- Indented-syntax `.sass` files aren't parsed.
- Classes generated by mixins/loops (`@each`, `#{$prefix}-x`) can't be resolved statically.
- Publishing to the Zed extension registry requires the server to be downloaded rather than bundled; to publish, put the server on npm and swap the embed for `zed::npm_install_package`.
